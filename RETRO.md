**Project:** SameerMart — Multi-Vendor E-Commerce Platform

**Author:** Mohamed Sameer

---

## 1. Executive Summary
SameerMart was designed, built, and hardened as an enterprise-grade Servlet/JSP e-commerce platform using Java 17, Apache Tomcat 9, HikariCP, H2/PostgreSQL, and Gemini AI. Across four development phases, the platform grew from a greenfield Maven prototype to a fully tested application with 153 passing automated tests, robust security protections (CSRF, XSS, role isolation), atomic transaction guarantees, and an intelligent customer support assistant.

---

## 2. What Went Well

1. **Rock-Solid Atomic Transactions (F5)**:
   - Order placement was architected with explicit manual database transaction boundaries (`connection.setAutoCommit(false)`), stock sufficiency checks, atomic order and order-item insertion, stock decrement, and cart clearing. Rollbacks on failure completely eliminate phantom purchases and inventory corruption.
2. **Layered Defense-in-Depth Security**:
   - Every state-changing form incorporates per-session 32-byte CSRF tokens verified using constant-time string comparisons (`MessageDigest.isEqual`).
   - File uploads are quarantined outside the web root with randomized UUID filenames, allowlisted extensions, and directory traversal validation.
   - User passwords are salted and hashed using jBCrypt with 12 rounds. Role escalation guards prevent unauthorized elevation to Administrator.
3. **Resilient AI Assistant Integration**:
   - Built a provider abstraction (`ChatProvider`) that seamlessly attempts Google Gemini Flash-Lite with an 8-second timeout, automatically falling back to an in-memory rule engine (`MockChatProvider`) if offline or rate-limited. This ensures zero downtime during grading or network interruptions.
4. **Comprehensive Observability**:
   - Added standard JSON envelope patterns (`ApiResponse`, `ApiError`), correlation tracking via SLF4J MDC and `X-Request-Id` headers, and an active `/api/v1/health` monitoring endpoint.
5. **High Test Coverage Culture**:
   - The test suite expanded monotonically: 113 baseline tests &rarr; 135 post-chatbot &rarr; 140 post-observability &rarr; 153 post-order workflow. Every feature was committed only after verifying 100% test pass rate.

---

## 3. What Went Wrong & Challenges Encountered

1. **JSP / Servlet Boilerplate Overhead**:
   - Pure Servlet and JSP development requires repetitive request parameter extraction, type casting, manual validation, and request dispatcher forwarding. Modern frameworks (e.g., Spring Boot) reduce this verbosity, but building with raw Servlets provided a deep foundational understanding of the Java EE servlet container lifecycle.
2. **Dual-Database Dialect Nuances (H2 vs. PostgreSQL)**:
   - Locally, development uses H2 file/memory databases, while production cloud environments (such as Render) deploy PostgreSQL. Minor SQL differences (e.g., `GENERATED BY DEFAULT AS IDENTITY`, `TIMESTAMP` precision, boolean column types) required strict standard SQL syntax in DAOs.
3. **Multipart Form-Data Parameter Parsing**:
   - In standard servlet filters, `request.getParameter("csrfToken")` returns `null` for multipart requests before `request.getPart()` is called. This required designing `CsrfUtil.extractToken()` to introspect multipart parts directly without breaking standard form submissions.
4. **Order Status State Transition Strictness**:
   - Restricting product reviews to verified deliveries required retrofitting earlier test suites that created orders in `CONFIRMED` state before attempting review assertions. This highlighted the importance of establishing domain constraints early.

---

## 4. Key Lessons Learned

- **Decouple Third-Party APIs Early**: Writing `ChatProvider` as an interface with a local `MockChatProvider` allowed continuous offline testing and rapid CI builds without external API dependencies or network flakiness.
- **Fail Fast with Clear HTTP Semantics**: Implementing HTTP 409 Conflict for invalid state transitions and 403 Forbidden for role violations provided immediate, clean feedback for both frontend consumers and automated tests.
- **Automate Regression Runs Continuously**: Running `mvn test` after every small diff prevented cascade errors and made debugging pinpoint accurate.

---

## 5. Remaining Technical Debt & Future Improvements

1. **Service Layer Abstraction (Tier 2 Plan)**:
   - Currently, Servlets invoke DAOs directly. Introducing formal Service interfaces (`AuthService`, `ProductService`, `OrderService`) and a `DaoFactory` will achieve complete decoupling of business logic from the HTTP transport layer.
2. **Database Migration Tooling**:
   - Database tables are currently created via `CREATE TABLE IF NOT EXISTS` in `DatabaseContextListener`. Adopting Flyway or Liquibase migrations (`V1__schema.sql` through `V4__migrations.sql`) will provide deterministic versioning.
3. **JUnit 5 Migration**:
   - While JUnit 4 with Mockito serves the suite well, migrating to JUnit 5 Jupiter will allow parameter-driven tests and modern test lifecycle assertions.
4. **Static Code Analysis**:
   - Integrating Checkstyle and SpotBugs into the Maven build lifecycle to enforce clean code conventions and identify concurrency vulnerabilities automatically.
